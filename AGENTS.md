# Repository Guidance

- Read `PROJECT_CONTEXT.md` for product direction and architecture constraints.
- Read `PROJECT_STATUS.md` before changing behavior, fixtures, or tests.
- Update `PROJECT_STATUS.md` in the same task when implementation status,
  priorities, verification results, or regression coverage changes.
- Distinguish automated tests, manual checks, and unverified behavior. Never
  describe a passing test suite as proof that the project has no bugs.
- Keep durable architecture guidance in `PROJECT_CONTEXT.md`; keep the live
  implementation ledger and next work in `PROJECT_STATUS.md`.
